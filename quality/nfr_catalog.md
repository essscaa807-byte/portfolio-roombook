# Каталог нефункциональных требований — RoomBook

Каждое требование имеет целевое значение и метод проверки. Если метод проверки не сформулирован
как измеримая процедура — требование считается неготовым.

| ID | Категория | Требование | Целевое значение | Метод проверки | Инструмент |
|---|---|---|---|---|---|
| NFR-PERF-001 | Производительность | Время ответа `GET /rooms` и `GET /rooms/{id}/slots` | p95 ≤ 300 мс, p99 ≤ 600 мс при 50 RPS | нагрузочный тест 30 мин, отчёт перцентилей | k6 |
| NFR-PERF-002 | Производительность | Время ответа `POST /bookings` (без внешнего календаря) | p95 ≤ 500 мс, p99 ≤ 900 мс при 20 RPS | нагрузочный тест, отдельный профиль «создание» | k6 |
| NFR-PERF-003 | Производительность | Формирование CSV-отчёта за квартал | ≤ 5 с на 10 000 броней | замер на синтетическом наборе | скрипт-генератор данных |
| NFR-REL-001 | Надёжность | Доступность API | ≥ 99,5% в календарный месяц (≤ 3 ч 39 мин недоступности) | расчёт по логам мониторинга | Prometheus + правило SLO |
| NFR-REL-002 | Надёжность | Потеря данных при сбое (RPO) | ≤ 15 минут | имитация падения, сверка объёма данных | тест восстановления бэкапа |
| NFR-REL-003 | Надёжность | Восстановление после сбоя (RTO) | ≤ 1 час | учения: поднять систему из бэкапа | runbook + замер |
| NFR-REL-004 | Надёжность | Повторная публикация события в календарь | ≤ 3 попыток, паузы 1/5/15 с | имитация недоступности внешнего сервиса | интеграционный тест с моком |
| NFR-SEC-001 | Безопасность | Аутентификация | JWT, срок ≤ 8 часов, подпись HS256/RS256 | проверка токена в тесте + попытка подделки | pytest |
| NFR-SEC-002 | Безопасность | Хранение паролей | bcrypt, cost ≥ 10 | ревизия кода + тест, что пароль не хранится в открытом виде | статический анализ |
| NFR-SEC-003 | Безопасность | Разграничение ролей | 100% админ-эндпоинтов возвращают 403 для EMPLOYEE | тест-кейс на каждый `/admin/*` эндпоинт | pytest (parametrize) |
| NFR-OBS-001 | Наблюдаемость | Журнал аудита админ-действий | 100% отмен и созданий комнат с actor, timestamp, payload | проверка логов после сценария | pytest + grep по журналу |
| NFR-DATA-001 | Данные | Хранение времени | все метки `timestamptz` в UTC, преобразование только на границе API | схема БД + тест «в БД 07:00Z, в ответе 10:00+03:00» | миграции + pytest |

## Соглашения

- Перцентили считаются на боевом профиле запросов, а не на синтетике из одного эндпоинта.
- Нагрузочные цели относятся к MVP-инфраструктуре: 2 vCPU, 4 ГБ RAM.
- Требования REL-002/003 для MVP считаются на файловом бэкапе БД; при переезде на PostgreSQL
  метод проверки не меняется, меняется инструмент (PITR).
